# API 导入时发现的数据问题

[chinese-poetry-api](https://github.com/palemoky/chinese-poetry-api) 把本仓库导入 SQLite 时发现的问题。统计基于 `fix-typo` 分支 4978df3。逐条清单（2206 条）见 [`API导入问题清单.tsv`](API导入问题清单.tsv)：id 列沿用 `人工复核清单.tsv` 的 `文件#下标` 写法，下标从 0 开始。

## 需要在本仓库修复

| 问题 | 条数 | 说明 |
|---|---:|---|
| 唐宋重复收录 | 218 | `全唐诗/poet.song.*` 与 `poet.tang.*` 中作者、正文完全相同的同一首诗，多为五代入宋的诗人（幸夤遜、朱存等）。需确认归属后保留一条。 |
| 正文为空或只有标点 | 347 | 如 `paragraphs: []`、`["。"]`，以及「存目」「（以上劉瑛整理）。」一类整理说明。应补全或删除，说明文字可移入 `notes`。另有 2 首正文含空段。 |
| 空标题 | 169 | 168 首在 `poet.tang.*`，1 首在 `唐诗补录.json`。部分是残句，部分正文也只有「。」。 |
| 作者名含缺字/括注 | 45 个名字 | 如 `[嚴]續姬`、`耿[湋]`、`□馮`、`雍州率□□□`、`敦煌人作品[一]`。括注会成为作者名的一部分，`耿[湋]` 与 `耿湋` 因此被当成两个人。 |

### `loader/datas.json`

- `songci.excludes` 写的是 `authors.song.json`，实际文件名是 `宋词/author.song.json`（单数）。这个文件现在会被当作诗词读进来，只是因为没有 `paragraphs` 才被丢掉。
- `全唐诗/唐诗三百首.json` 和 `宋词/宋词三百首.json` 不在 `excludes` 中，会作为重复数据再导入一遍（API 侧会去重，但其他使用 `datas.json` 的工具不会）。
- `蒙学/` 不在 `datas.json` 中（`nalanxingde` 的注释里说明过）。
- `幽梦影/youmengying.json` 只有 `content` 与 `comment` 字段，没有作者，API 侧只能写死为张潮。可以考虑在数据里补上 `author`。

## 已在 API 侧修复，本仓库无需改动

以下问题出在 chinese-poetry-api 的导入程序，不是数据本身的问题：

- **宋诗被标成唐诗**：`tangsong` 数据集（全唐诗全宋诗）被整体判为唐，导致约 25.5 万首宋诗标成唐代（发布版统计为唐 310576 / 宋 21110）。现在按文件名 `poet.song.*` / `poet.tang.*` 判定。
- **简繁两表作者 ID 对不上**：作者 ID 由随机顺序的自增列分配，两张表的 343918 首诗作者 ID 全部不一致。现在两张表共用一套显式分配的作者 ID。
- **繁体表把繁体原文又做了一遍简转繁**：`十里→十裏`、`咸→鹹`、`陸游→陸遊`（9271 首挂在「陸遊」名下）。抽样中约 35% 的全唐诗正文被改动过。现在逐首判断源文本是简体还是繁体，只在与目标字形不同时才转换。

- **同名异人被合并**：作者以名字唯一，唐代张潮与清代张潮、各朝代的「佚名」都被并成一人。现在按「名字 + 朝代」区分作者，`?author=张潮&dynasty=清` 即可指定。
- **诗人小传未导入**：现在已导入 `authors.tang.json`、`authors.song.json`、`宋词/author.song.json` 与南唐 `authors.json` 中的小传（13653 位作者中 12293 位有小传）。

数据仓库只需保持各文件内部用字统一。目前的情况是：全唐诗、孟子为繁体（全唐诗中有 34 首判为简体），其余数据集为简体。
