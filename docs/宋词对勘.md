# 宋词对勘

把 `宋词/` 中约 2.1 万首、30 万句（含《宋词三百首》选本）逐句与古籍比对，找出形近、音近的错字（如「春垂重」→「春睡重」）。

> **已完成。** 检索、审核和复核都已结束，`collate-songci.yml` 与 `recheck-songci.yml` 已删除，要对勘其他合集可从 git 历史恢复。下文的 Actions 流程和 artifact 下载命令保留作记录，已不能直接运行。

这项工作需要约 **9.6 万次**识典古籍检索。为了不给识典古籍造成压力，由 GitHub Actions（`collate-songci.yml`）**每天定时运行一次、每次检索 1200 条**，约 80 天完成；人只需隔一段时间审核一次结果。

## 为什么做

2026-10 抽样评估（每部随机 200 首、各取 2 句，到识典古籍检索比对）：

| 合集 | 原样得到古籍证实 | 他本异文 | 疑似错字 | 未检索到 |
|------|------|------|------|------|
| 宋诗（全唐诗/poet.song.*） | 277 | 78 | 1（实为异体） | 44 |
| 宋词 | 292 | 78 | 8（核实约 4 处真错字） | 22 |

宋词约 1% 的句子含可检出的错字，推算全书约 2000 处；宋诗几乎没有，暂不对勘。唐诗已用 全唐诗 ↔ 御定全唐詩 两份录文对勘完成（见 README；御定全唐詩 随后已删除）。

## 判定规则

只改「**有充分依据**、且**本库读法无任何依据**」的字：

- **只看一字之差**：古籍中与本库句子同长、且只差一个字的读法。
- **改**：他本读法有 **≥ 2 种**古籍支持，且检索到的古籍中**没有一种**是本库读法。
- **不改**：
  - 两种读法都有古籍 → 版本异文
  - 一为常用字、一为生僻字（如 卮/巵）→ 异体
  - 古书通用字（如 閒/間、蹤/縱、坐/座）
- 比对前统一异体（OpenCC 繁简转换 + Unicode Unihan 语义 / 字形异体），避免把异体差异误判为错字。
- 自动判定只是建议：每一处都会出现在审核表 `review.tsv` 中，由人确认后才写回。

## 自动检索（GitHub Actions）

workflow 每天北京时间 03:00 运行（约 2 小时，每条检索平均约 6 秒）：

1. 按当前数据生成检索计划（`collate.py plan`）
2. 检索识典古籍 1200 条（`search.mjs --limit 1200`，每条间隔 3～4.5 秒）
3. 判定检索已全部完成的词（`collate.py analyze`），进度表写在运行页面的 Summary 中
4. 上传审核表 artifact `collate-songci-review`（`review.tsv`、`state.json`、`plan.json`）

- 检索结果缓存在 Actions cache 中，逐日累积；中途失败或超时也会保存，下次自动从断点继续。cache 连续 7 天未使用会被 GitHub 清除，届时从头检索。
- 想临时多跑一些：在 Actions 页面手动运行（Run workflow），可填写本次检索条数（每次不超过 2000 条，否则可能超出 4 小时时限）。请勿缩短间隔或并行多开。
- 已写回或否决的句子记在 [`宋词对勘.applied.json`](宋词对勘.applied.json)，随仓库提交，之后的审核表不再出现。

## 审核与写回（攒到几十处时做一次即可）

```bash
pip install opencc-python-reimplemented                      # 只需一次
W=~/.cache/chinese-poetry/songci-review && rm -rf $W
gh run download --repo palemoky/chinese-poetry -n collate-songci-review -D $W   # 下载最近一次运行的审核表
```

1. 打开 `$W/review.tsv`，逐行看 `original`（本库）、`proposed`（建议）和 `evidence`（支持的古籍）。
2. 逐条填写 `decision` 列（默认留空，留空的行不写回；表中混有版本异文和断句不同造成的「一字之差」，不要整列采纳）：
   - `accept`：采纳建议
   - `reject`：不改，以后不再出现
   - 直接填写正确的整句：按你的写法改
3. 写回数据、记入 `fix_progress.json` 与 `宋词对勘.applied.json`，并更新本文档的进度：

```bash
A=docs/宋词对勘.applied.json
python3 scripts/collate.py apply  --work $W --applied $A --reviewer <你的名字或 GitHub ID> --date YYYY-MM-DD
python3 scripts/collate.py report --work $W --applied $A --doc docs/宋词对勘.md --date YYYY-MM-DD
git add 宋词 fix_progress.json docs/宋词对勘.md $A && git commit -m "fix: 宋词对勘 …"
```

## 本地运行（不用 Actions 时）

```bash
pip install opencc-python-reimplemented
(cd scripts/shidian && npm install && npx playwright install chromium)
W=~/.cache/chinese-poetry/songci      # 放在仓库之外：检索结果缓存会有数百 MB，不要提交
python3 scripts/collate.py plan --dir 宋词 --work $W
node scripts/shidian/search.mjs $W/queries.json $W/results.jsonl --limit 1200
python3 scripts/collate.py analyze --work $W --applied docs/宋词对勘.applied.json
```

本地与 Actions 的检索缓存互不相通，请只用其中一种，避免重复检索。

## 复核既往判定（GitHub Actions）

审核时 3,136 处多凭语感判定。留空的 168 处逐条查证后 76% 要改，说明其余判定也需要查书。因此以 [`scripts/recheck.py`](../scripts/recheck.py) 对其余 2,968 处（快照 [`宋词对勘.recheck.tsv`](宋词对勘.recheck.tsv)）重新取证：用差异字左右两侧的上下文检索，检索词不含差异字，统计各书在该位置的用字。

- workflow `recheck-songci.yml`（已删除）每 4 小时运行一次，每次 2000 条，共 5,464 条。
- 结果在 artifact `recheck-songci` 的 `recheck.tsv`，只列出与既往判定不一致的条目：`overturn_reject`（当时否决，可能漏改）、`overturn_accept`（当时采纳，可能改错）、`weak`（证据不足）。
- 只是建议，须逐条人工审核；已关闭的条目不会回到 `review.tsv`，不能用 `collate.py apply` 写回。

### 复核结果（2026-11-01）

5,464 条检索全部完成：一致 983、`overturn_reject` 1,642、`overturn_accept` 33、`weak` 310。

`overturn_reject` 不能直接采信。审核表只收录本库读法未命中的句子，结果页又只有第一页约 10 条片段，所以“原读法 0 种书”多半来自筛选和截断。为此用**含本库读法**的 7 字串再做定向检索（共 2,398 条，覆盖 `overturn_reject` 和全部已采纳条目）：

| 分组 | 条目 | 本库读法有书支持 |
|------|------:|------:|
| `overturn_reject` | 1,642 | 306 |
| 既往采纳 | 690 | 46 |
| 查证后采纳 | 120 | 15 |

裁定写在 [`宋词对勘.recheck-decisions.tsv`](宋词对勘.recheck-decisions.tsv)，用 `python3 scripts/recheck.py apply --reviewer <名字> --date YYYY-MM-DD` 写回：

- `revert` 33 条：原读法有书支持且讲得通，属异文，撤销当时的改动。原读法只在单一本子出现且不成词的（如 孤兔、晚两、残戌），视为 OCR 或刻本讹误，不撤销。
- `fix` 106 条：定向检索仍查不到本库读法、读法讲不通，建议读法至少 2 种书支持。
- 其余 1,230 处定向检索也查不到本库读法，但两种读法都讲得通（或只是用字不同）的按异文保留。这部分依赖人工语义判断，后来者可继续复核。
